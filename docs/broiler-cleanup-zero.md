# Broiler Clean Up after harvest

Posted reversal: apply `app/brd/cu/reverse_br_cleanup_transaction.sql` after the cleanup update and farm-cycle schema. This migration has been tested locally, not deployed to the app's target. Reapply it after an older cleanup/notification migration that replaces the event hooks. The Clean Up list and posted document expose Reverse, controlled by `conVoid` and `/brd/cu/void`. A reason of 1–1000 trimmed characters is required. The RPC validates an active user, Void permission, Broiler FMS and active numeric farm assignment (Super Admin bypasses permission/assignment checks), and the canonical persisted document farm. It uses SECURITY DEFINER so dependency checks cannot miss rows hidden by another user's RLS; only authenticated callers may execute it, and all access checks run inside the function.

Reversal retains the document with internal status `Cancelled`, displayed as **Void**, plus reason, actor and timestamp. Original lines/postings stay intact. `BR_CLEANUP_REVERSAL` and `BR_CLEANUP_VARIANCE_REVERSAL` restore each original OUT as an IN, including quantity zero; a unique FK link and validation trigger tie each reversing entry to its source. A separate cleanup link avoids changing Growing's reversal contract. Summary totals net the original and reversing entries, and Warehouse Report links reversals to the cleanup document.

The RPC blocks newer building/farm cycles and subsequent inventory postings, Harvest/Clean Up drafts or edits, Growing updates and DOC Receiving rows in each affected building. It holds transaction locks while checking and writing. Every original closed cycle must still belong to the cleanup. It restores building status to `Saved`, removes closeout metadata and reopens the associated closed farm cycle. Multi-building reversal is all-or-nothing. Local PostgreSQL checks cover ordinary and zero reversal, all quantities/variance, cycle reopening, permission/reason/farm denials, newer cycles, later transactions, authenticated execution, multi-building failure, an injected late failure with complete rollback, request/recipient deduplication, no-rule no-op and invalid missing-farm routing. Production RLS and deployment remain separate verification steps.

The existing number-based draft recovery now happens inside that transaction. Identical request retries return the saved result.
